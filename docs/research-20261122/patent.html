專利版：技術有沒有真的透過引用形成連結？

從一件專利、一條引用箭頭開始，逐步看懂專利網絡、公司網絡、兩種不同的 O/E 統計，以及為什麼「未偵測超額仲介」不能簡化成「不存在結構洞」。

先看專利資料卡先看結論
先記住：專利版的連線和文獻版不同。文獻版的邊是文章裡的功能關聯；專利版真正有專利 P2 引用 P1的引用方向。但是「專利引用」仍不等於企業內部真的把 A 的輸出交給 B。
① 專利資料② 引用箭頭③ 領域引用 O/E④ 專利／公司⑤ 仲介 O/E⑥ 限制度⑦ 結論
專利版 · 01

第一步：專利資料裡有哪幾種不同紀錄？

對應公式與規則
Patent ID → Citation（引用）
Patent ID → Assignee（公司）
Patent ID → CPC（分類）

同一專利可以有很多 CPC 分類、引用多件專利，甚至涉及多個申請人。資料表若直接 join 而不處理一對多，會把同一件專利重複算很多次。這是資料治理要求，不能假設所有原始關聯已無誤。

實際能確認的事

可以明確分辨「發明是哪一件」、「引用哪件」、「由哪家公司持有」。

目前不能推出的事

不能把專利資料中的「公司」等同特定員工的決策，也不能把引用數直接當作企業採用數。

資料依據：USPTO PatentsView 官方資料入口；研究乙來源說明（私人庫）。

專利版 · 02

第二步：專利引用網絡跟文獻共現網絡差在哪？

對應公式與規則
eu,v=1，若專利 u 引用專利 v
方向：u → v

引用有方向和年份；共現通常只表示兩個功能在相同文件同時出現。研究可用引用方向建網，再檢查特定類別跨群的連線與替代路徑；但究竟如何處理有向／加權必須依實際程式設定。

實際能確認的事

可以問「專利間是否存在有向知識引用連結」與「這些連結是否跨 AI／決策類別」。

目前不能推出的事

不能把專利引用直接解釋成即時的技術輸入輸出依賴或企業工作流程。

資料依據：專利網絡 R2 原始 JSON；文獻版的不同連線。

專利版 · 03

第三步：先前為什麼有的專利研究說 3.05，有的說 0.35？

對應公式與規則
OE = O/E
研究二：3.05（相對判準）
專利第二輪：0.353／0.380（絕對判準）

這些是領域引用流動的 O/E：研究二的 3.05 [2.94,3.17] 是研究層級唯一預先登錄的相對判準結果，未支持其相對結構洞假說；專利第二輪以事先凍結的絕對 O/E<1 規則得到 HOLE_SUPPORTED。母體、參照、估計對象及判準不同，並非程式算出互相矛盾的同一個統計量。後續全體專利參照 2.81–3.90 僅供探索性討論。

實際能確認的事

可以說結果對比較母體和事先選擇的判準敏感，而且兩種相反判定必須一併呈現。

目前不能推出的事

不能只選較漂亮的 0.35 或 3.05，也不能把事後全體參照拿來覆寫事前凍結結果。這裡的 0.353／0.380 與下一節跨群仲介的 0.3556 不是同一個 O/E。

資料依據：研究乙 F 層：研究二與專利第二輪對照（私人庫）。

專利版 · 04

第四步：為什麼專利網絡和公司網絡要分開？

對應公式與規則
Gpatent=(Vpatent,Ecitation)
Gfirm=(Vfirm,Ecitation-aggregated)

專利網絡每個節點是專利；公司網絡則把專利與公司身分整合後形成不同的節點集合。公司多、專利多或引用多，都可能改變網絡密度與節點度數，所以不能直接比較兩張圖的原始 Burt 數值。

實際能確認的事

專利版已存在兩張引用分析網絡：38,322 專利／101,630 條引用連線，與 4,537 公司／13,312 條公司連線。

目前不能推出的事

不能把專利網絡和公司網絡當成兩份完全獨立的外部驗證，因為兩者共用底層專利資料。

資料依據：專利網絡原始 JSON；公司網絡原始 JSON。

專利版 · 05

第五步：和隨機網絡相比，跨群仲介多還是少？

對應公式與規則
O/Eliaison=實際跨群路徑 / 零模型平均路徑
專利：340,150 / 956,447.255 = 0.3556
公司：51,906 / 81,117.49 = 0.6399

兩張網絡各有 200 次零模型模擬，維持原報告的網絡設定。圖中百分比只是各自的 O/E×100，不代表兩張圖的原始分母相同。原輸出標籤皆為 NOT_DETECTED_UNDER_THIS_NULL；報告中的 p=1.0 不表示「零假說一定是真的」。

實際能確認的事

既有零模型下，兩張網絡都沒有偵測到超出隨機期望的跨群仲介。

目前不能推出的事

不能用「低於隨機」推斷所有節點都沒有局部結構洞；也不能把這組 liaison O/E 和上面領域引用 O/E 混成一個統計量。

資料依據：專利 200 次零模型結果；公司 200 次零模型結果。

專利版 · 06

第六步：那我們有算 Burt 限制度嗎？

對應公式與規則
Ci=Σj(pij+Σqpiqpqj)²
數值越低，通常代表約束較小

既有摘要有各類別節點平均 Constraint：專利 AI_only=.5996、BOTH=.5512、DEC_only=.6111；公司 AI_FIRM=.6341、MIXED=.4281、DEC_FIRM=.7582。這些是群平均，未控制各組度數、強度和密度。現有兩份 JSON 沒有提供足以直接與文獻版比較的 Effective Size 零模型顯著性檢定。

實際能確認的事

我們能看到不同專利／公司類別的平均網絡約束不同，也能把觀測指標與跨群零模型分開報告。

目前不能推出的事

不能只因 MIXED 公司平均 Constraint 較低就宣稱它們必然具有顯著的仲介優勢，也不能拿專利版 .428 與文獻版 .233 比較誰「更有洞」。

資料依據：專利群組平均限制度；公司群組平均限制度。

專利版 · 一頁總結

專利版可以對教授說什麼？

38,322專利引用節點
4,537公司引用節點
0.3556專利仲介 O/E
0.6399公司仲介 O/E

「我們換用具有明確引用方向的專利資料，建立專利和公司兩種網絡，並和指定零模型比較。結果在這兩張網絡中都沒有偵測到比隨機參照更多的跨群仲介。但這不代表整個領域沒有局部結構洞，也不表示領域引用流動的所有檢驗都得出一致判定。」

已有計算證據

專利／公司網絡、群組平均 Constraint、各 200 次零模型、跨群仲介路徑 O/E。原始 JSON 已核對。

仍有測量限制

這次網站沒有重新從原始引用資料全量建網；兩個網絡共用底層專利資料，兩份 JSON 沒有和文獻版一致的 ES 顯著性檢定；企業實際行動仍無直接資料。
