圖四 · 為什麼要引入專利？

因為專利可以讓我們多看幾種「連結」，但每種連結仍有各自限制

文獻矩陣只記錄作者怎麼談功能。專利則可能同時提供技術文字、分類碼、專利間的引用，以及申請人／權利人資訊。這讓我們能從好幾個角度核對「兩項功能是否被分開」「是否有知識傳遞」「誰可能在中間」。但並不是每件專利都能取得完整文字，也不能把引用當成企業系統內真的 A→B 使用關係。

虛構示例｜不是資料庫裡的一件真實專利一個專利的不同欄位，能回答不同問題
技術摘要或權利項包含 AI 預測與排程

只能先說可能包含兩項功能。若原文說「預測值輸入排程器」，才有較直接的功能依賴文字證據。

CPC 分類可能被分入兩組碼

兩個碼共同出現是分類標記；不同年度可能有代碼調整，不能把更名當融合。

專利引用P2 引用了 P1

代表資料庫記錄一條有向引用關係；不必然代表 P1 的 AI 輸出真的成為 P2 的決策輸入。

申請人／公司公司 X 持有 P1、P2

可以檢查公司知識組合與網絡位置；不能直接推導員工有使用或公司管理已有效整合。

圖五 · 同一主張如何經不同資料反覆檢查

從「低整合」到「真的有結構洞」——專利驗證的六道關卡

這不是把一件專利重複算六遍就算六次獨立證明，而是用不同的觀測、不同的模型和事先凍結的判準檢查同一個解釋。任何一道關卡資料不足，都只能停在該層結論。

三種不同公式的差別：讓老師知道我們到底「算了什麼」

文獻矩陣的基準

Ead = (ka × kd) / M

比較功能配對在文獻中出現得多不多。

專利引用的 O/E

O/E = 觀察引用量 / 期望引用量

比較特定零模型下的引用流動。正式分析依年份分層。

Burt Network Constraint

ci = ∑j(pij + ∑q piqpqj)2

衡量行動者連帶冗餘與約束。不是用專利 O/E 自動換算而來。

各式子使用不同節點、連線與估計對象，不能把它們當成同一個「洞」的三種算法。完整公式請參照下方來源。

關鍵研究問題：只把專利打散成 A、B、C 多標籤（M1），和補入「A 的輸出被 B 使用」的可追溯關係證據（M2），哪一種能恢復真正的依賴？目前只有合成反例與實驗設計；沒有完成真實確認性人類驗證。
給教授的兩分鐘口頭講法

順著圖講，老師不需要先知道任何統計公式

「老師，我們先從您說的 A—B—C 開始。B 如果整個被拿掉，是節點消失、網絡可能斷裂；但 Burt 特別關心的是 B 還在，A 和 C 卻沒有直接連線，所以 B 可能有仲介位置。

我們原始論文的 A、B、C 其實不是人，而是 AI 和決策的功能類別。我們在文獻中發現有 16 組配對比期望少，而且另外有 16 格完全沒有觀察到。『比期望少』『觀察為零』和『Burt 洞』是不同概念。

所以後續我們才引入專利，從技術文字、分類版本、引用方向、專利和公司網絡反覆交叉檢查，看看文獻中少出現的配對，能否推論成實際知識流動少、缺乏仲介，甚至功能之間沒有真實依賴。

目前的結果很重要：不同的事前判準和參照會得到不同的標籤，分類版本也會改變一些結果。因此我們不能先宣布一定有洞或一定沒洞。下一步要用新的專利樣本，讓兩位真人判讀 A 的輸出究竟有沒有被 B 使用，再決定單純打散功能是否足夠。」
