## Method

Each flagged cell was handled on its own; there was no bulk replace.

1. **Find the flags.** Every cell matching `2026-09-29|待核|20260929` was located.
   - CSV: 16 cells, all in column 13 `Network status`, rows 2–17 (G01–G16).
   - XLSX: the same 16 cells in `G_to_M_matrix!M2:M17`, plus the legend cell `README!A8` that describes the flag ("user-reported … not in the workspace").
2. **Verify each G row.** The row was looked up in `ROBUST_CORE_LOCAL_SENSITIVITY.csv` by its exact (AI family, Decision family) pair. A row counted as verified only if **all** of the following held:
   - the row exists;
   - `official_core_member=YES` and `official_core_direction=DEPLETED`;
   - `sidecar_core_member=YES` and `sidecar_core_direction=DEPLETED`;
   - `core_membership_changed=NO`;
   - the 132 `O (doc-level edges)` value equals `official_observed`;
   - the same G ID, pair and directions appear in V1.8 `04` Table T2.
3. **Write the new wording.**
   - Verified rows: only the flag span `〔2026-09-29 紀錄，待核〕` was replaced, by `〔VERIFIED_SOURCE: …〕`. That fragment names the source file, its sha256 prefix, the row and the checked fields, and states the scope (local label-replacement sidecar, not a full reanalysis).
   - The rest of each cell is unchanged, including `證據單元：邊界敏感` for G07 and G15.
   - A failing row would have kept its pending wording. None failed.
4. **Update the README legend.** `README!A8` was rewritten (starting `VERIFIED_SOURCE:`) only after all 16 rows had verified.
5. **Write the copies.**
   - CSV: written by line-level substitution, so every other byte is identical. Checks: the BOM is kept, there are 0 CR characters, and the trailing newline is unchanged.
   - XLSX: loaded with openpyxl using `data_only=False`, so formulas are kept; only the planned cells were assigned; then saved.

Every replacement fragment contains no ASCII comma and no double quote, so the CSV quoting is unchanged.
