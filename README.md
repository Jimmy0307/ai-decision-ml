## Research scope

The research object is **enterprise-wide AI adoption**, not any single department, process, or use case. The nested architecture is:

`Enterprise > Business Unit / Function > AI Initiative / Shared Capability > Role-specific Users`

The evidence chain is:

`AI × Decision corpus → G01–G16 structural research leads → M1–M4 organizational mechanisms → enterprise governance/capability allocation → business-unit configurations → user responses → enterprise value realization`

## Methodological invariants

- G01–G16 are literature-network leads, not company problems or utility weights.
- M1–M4 form the static organizational mechanism layer; M5 requires longitudinal evidence.
- Enterprise–Business Unit is the default optimization hierarchy.
- Role-specific users are modeled by conditional response distributions unless evidence justifies a true third optimization layer.
- Ordinal constructs are used only as within-construct thresholds or lookup keys; they are never treated as cardinal utility.
- Observed, elicited, public, scenario, simulated, and optimized values remain separated.
- Missing values remain `UNIDENTIFIED`; they are never silently filled with zero or legacy synthetic coefficients.
- Shared platform/governance/infrastructure costs are separated from local implementation costs.
